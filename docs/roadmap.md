## Этап 3 — финансы (не начат)

`accounts`, `transactions`, `categories`, `budgets`, `savings_goals`.
Связка `order → transaction` возможна только после того, как в Этапе 2
появится таблица `orders` с реальной суммой заказа.

## Этап 4 — оплата (не начат, осознанно)

Требует выбора платёжного провайдера с эквайрингом (ЮKassa/CloudPayments
и т.п.) — сохранённая в аккаунте магазина карта для ручной оплаты не
равна автосписанию через бота. Пока не решено — оплата остаётся ручным
шагом пользователя, это не костыль, а осознанная граница безопасности.

## Этап 5 — AI-ассистент верхнего уровня (не начат)

Вопросы вида «сколько потратили на продукты в этом месяце» — возможны
только после Этапа 3.

## Следующий конкретный шаг

Единственное, что реально блокирует Этап 2 — селекторы Ленты. Это может
сделать только тот, у кого есть живая авторизованная сессия в браузере
(через Claude в Chrome), сама песочница до сайта не достаёт.

Чек-лист, что нужно снять с реального DOM `online.lenta.com`:
1. Селектор строки поиска (сейчас: `input[placeholder*="Найти" i]`)
2. Селектор карточки товара в выдаче (сейчас: `[class*="product-card" i]`)
3. Селектор кнопки «В корзину» внутри карточки
4. Селектор/URL ссылки на корзину (сейчас: `a[href*="basket" i]`)
5. Как выглядит блок «итого» в корзине — по нему парсим сумму заказа
6. URL и селекторы экрана оформления/оплаты — куда именно должен
   долетать `lenta_checkout_link` и что значит «дошли до оплаты»

Как только это есть — обновляю `mcp-servers/lenta-mcp/src/tools/*.js`,
прогоняю `npm run auth` → `lenta_search` → `lenta_cart_add` →
`lenta_checkout_link` вживую, и только после этого добавляю запись
реального заказа в таблицу `orders`.
