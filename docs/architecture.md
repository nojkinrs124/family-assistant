# Архитектурные решения

## Почему MCP, а не самописный REST между ботом и магазинами

ВкусВилл уже раздаёт официальный MCP-сервер (`mcp.vkusvill.ru/mcp`) с тулами
`products_search` / `product_details` / `cart_link_create`. Чтобы Shopping
Agent мог одинаково работать и с ним, и с магазинами без официального API
(Лента), у обоих один и тот же интерфейс — набор MCP-тулов. Добавление
нового магазина = новый MCP-сервер, без изменений в боте.

## Почему браузерная автоматизация, а не парсинг API Ленты

У Ленты нет публичного API для сторонних заказов. Есть два пути: реверс
внутреннего мобильного API (хрупко, может нарушать ToS) или браузерная
автоматизация под настоящим аккаунтом пользователя. Выбрана автоматизация,
как более прозрачный и предсказуемый вариант.

## Сессия вместо пароля в коде

Скрипт `mcp-servers/lenta-mcp/src/auth.js` открывает видимое окно браузера,
пользователь логинится сам (телефон + SMS), сессия (`storageState`)
сохраняется на диск и переиспользуется сервером. Пароль нигде не хранится
и не проходит через код. Проверено вручную (через Claude в Chrome, 17
августа 2026): наполнение корзины на online.lenta.com не требует капчи;
SMS-код запрашивается только на шаге логина при оформлении заказа.

## Где останавливается автоматизация

`lenta_checkout_link` доходит до корзины/чекаута и отдаёт ссылку + сумму,
но не завершает оплату. Экран оплаты сохранённой картой (один клик или
3-D Secure) ещё не проверен — см. пункт в README "что дальше". Пока это
не подтверждено, оплата в любом случае должна оставаться ручным шагом
пользователя — так безопаснее и не требует хранить платёжные данные.

## Известные ограничения текущего кода

- Селекторы в `lenta-mcp/src/tools/search.js` и `cart.js` — заготовки
  (`TODO`), не проверены на реальной вёрстке (у автора кода не было
  сетевого доступа к online.lenta.com). Нужно поправить через DevTools.
- `telegram-bot/src/mcpPool.js` подключает `lenta-mcp` как локальный
  сабпроцесс через `node <path>` — предполагает, что оба пакета лежат
  рядом в этом репозитории. При выносе в отдельные сервисы/контейнеры
  путь нужно будет заменить на HTTP/SSE-транспорт.
- В проде `session-state.json` должен лежать не на диске сервера, а в
  зашифрованном хранилище (Supabase Vault), по одному на `family_id` +
  `store_id` — сейчас, для одной семьи и одного магазина, файла на диске
  достаточно для проверки концепции.
- LLM tool-calling loop (OpenRouter, openai/gpt-4o-mini по умолчанию) в `agent.js` ограничен 12 шагами и не имеет
  ретраев/логирования в `audit_logs` — это будет добавлено вместе с
  Этапом 2 (когда появятся таблицы `orders`/`shopping_lists`).
